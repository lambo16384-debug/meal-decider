# 今天吃什麼｜餐點抽選器

## 1. 發想與目的
每天到了用餐時間，常常因為選項太多而不知道吃什麼。我想製作一個適合學生使用的餐點抽選器，讓使用者先設定預算與飲食偏好，再從符合條件的餐點中隨機選擇，減少決定午餐或晚餐的時間。

## 2. 使用者與情境
主要使用者是有預算限制、經常煩惱吃什麼的學生。使用者可以在手機或電腦開啟網站，選擇餐點類型、預算與是否只吃蔬食，按下抽選按鈕取得建議，也可以把自己喜歡的餐點加入清單。

## 3. 功能規格與驗收標準
| 功能 | 具體規格 | 驗收方式 |
| --- | --- | --- |
| 預算篩選 | 可設定 NT$50～300 的預算上限，間距 10 元 | NT$100 時，只會抽到價格不超過 100 的餐點 |
| 類型篩選 | 全部、飯類、麵類、輕食、異國、其他 | 選擇麵類後，候選清單與抽選結果只包含麵類 |
| 蔬食篩選 | 勾選後只保留標記為蔬食的項目 | 預算、類型與蔬食條件同時成立 |
| 隨機抽選 | 候選項目等機率抽選，顯示約 1 秒動畫後呈現名稱、價格、類型 | 連續操作可取得符合條件的結果；抽選中不能重複啟動 |
| 避免連續重複 | 開啟時，至少有兩個候選項目才排除上次抽中的餐點 | 有兩個候選時連續抽選不重複；只有一個時仍可抽選並說明原因 |
| 餐點管理 | 內建 18 種範例餐點；可新增自訂名稱、估計價格、類型、蔬食標記 | 新餐點加入候選，可排除或重新加入，也能刪除自訂項目 |
| 搜尋清單 | 依名稱尋找餐點，搜尋只影響清單顯示 | 搜尋文字不改變抽選池，介面明確說明 |
| 最近紀錄 | 顯示最近 6 次抽選與時間，可清除紀錄 | 第 7 次會移除最舊紀錄 |
| 本機保存 | 用 localStorage 保存自訂餐點、排除項目、篩選偏好與抽選紀錄 | 重新整理後可保留；儲存不可用時顯示提示並仍能操作 |
| 空結果處理 | 顯示沒有符合條件的餐點，停用抽選按鈕，提供重設篩選 | 低預算與狹窄條件不造成錯誤或無限動畫 |
| 表單驗證 | 名稱 1～24 字，估計價格為 1～9999 的整數，不允許同名餐點 | 不合法資料不加入，顯示可理解的錯誤訊息 |
| 響應式與無障礙 | 手機改為單欄；可用鍵盤操作；有標籤、焦點樣式與動態訊息 | 390px 與桌面寬度無水平溢出，降低動畫偏好會減少動畫 |

## 4. 網頁結構與設計
使用繁體中文介面，以奶油白、橘色與深灰色呈現輕鬆的用餐氣氛。頁首顯示名稱與簡短說明，主要區域包含篩選面板及抽選卡片；下方是候選餐點管理與最近紀錄。餐點以 emoji 呈現，所有字型使用系統字型，不依賴外部圖片或 CDN。

## 5. 技術與資料限制
HTML、CSS、JavaScript 全部放在單一 index.html，可直接開啟或放到 GitHub Pages。沒有伺服器、帳號、定位或外部 API。範例價格只是供篩選的估計值，不代表即時店家售價；蔬食標記由清單設定，使用者仍需向店家確認。資料僅保存於目前瀏覽器，不會跨裝置同步。清除網站資料會移除保存內容。

## 6. AI 協作紀錄
1. 先提供作業要求，和 AI 討論主題，選定「今天吃什麼：餐點抽選器」。
2. AI 將主題整理為上述功能、介面、技術與驗收規格。
3. 依規格製作單一 HTML，再透過實際操作檢查篩選、抽選、資料保存與手機版面。

後續修改與測試結果會記錄在「製作與測試紀錄.md」，只記錄實際發生的調整。


## 操作與製作驗證

直接開啟 index.html 即可操作，CSS 與 JavaScript 均內嵌，沒有外部套件。

已實際驗證預算與蔬食組合篩選、連續不重複、空候選、單一候選、新增與刪除、重複名稱驗證、本機保存、搜尋不影響抽選池，以及最近 6 次紀錄。桌面與 390px 手機版面已检查。測試後改善類型按鈕的鍵盤焦點保存，並加強儲存紀錄日期驗證。
